# Build My Home V4.9 — Cloud + Payment

V4.9 adds a real backend path without removing the local-first behavior of V4.8.

## What changed

- Supabase Auth: email/password sign-up, sign-in, refresh and sign-out through same-origin `/api/auth`.
- Multi-project Cloud: create/save/load/delete user-owned projects; auto-sync after a project is linked.
- Supabase RLS: each authenticated user can only read/write their own project rows.
- payOS: server-side payment-link creation for 99,000 VND. Client ID/API key/checksum key never ship to the browser.
- Webhook verification: HMAC-SHA256 validation before marking a payment paid.
- Entitlement table: Step 9/10 unlock only after the signed webhook creates a server entitlement.
- Payment return handling: re-checks server entitlement after returning from payOS.
- Local fallback: all planning functions still work without cloud credentials; payment remains disabled rather than faking success.

## Required production setup

1. Create a Supabase project.
2. Run `sql/V4.9_SUPABASE_SCHEMA.sql` in Supabase SQL Editor.
3. Create a payOS payment channel and obtain Client ID, API Key and Checksum Key.
4. Add the variables in `.env.example` to Vercel Environment Variables.
5. Deploy, then register `https://YOUR_DOMAIN/api/payment-webhook` as the payOS webhook URL.
6. Test with a real low-risk payment before publishing the checkout publicly.

## Security notes

- `SUPABASE_SECRET_KEY` and all payOS secrets are server-only.
- Project RLS is enabled and user ownership is checked server-side.
- Payment unlock is idempotent and validates order, user mapping, amount and webhook signature.
- The premium screens are still browser-rendered. A determined user can inspect bundled frontend code, so this version protects the actual entitlement/payment state but is not DRM. Server-only premium document generation can be moved into V5.0/V5.1 if stronger anti-tamper protection is required.
